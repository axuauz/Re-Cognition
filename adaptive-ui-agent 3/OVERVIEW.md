# Re:Cognition 한눈에 보기

사용자(페르소나)에 맞춰 웹페이지를 쉬운 화면·소리 중심 화면으로 다시 구성하는 Human-in-the-Loop 접근성 에이전트.
Chrome 확장(Manifest V3) · v2.0.0 · SDGs 10(불평등 해소) 대회 시연용.

> 설치와 실행 방법, 이름 규칙(표시 이름은 Re:Cognition, 코드 식별자는 `Equali*`)은 [README.md](README.md)에 있습니다.
> 이 문서에서 **부분**이라고 적은 곳은 구현이 구조도에 못 미치는 곳입니다. 숨기지 않고 그대로 적었습니다.

---

## 1. 역할 · 작동 흐름

### 역할

웹페이지는 하나인데 쓰는 사람은 제각각입니다. Re:Cognition 은 **사이트를 고치지 않고, 쓰는 사람 쪽에서** 화면을 그 사람에게 맞춥니다.

- **누구를 위해**: 어르신, 어린이, 시각장애, 저시력, 난독, 청각장애, 손 떨림, 그리고 직접 적는 '기타'
- **무엇을**: 복잡한 페이지를 큰 버튼 몇 개와 핵심 내용만 있는 화면으로 다시 구성하거나, 소리로 읽어 주거나, 원래 화면의 모양만 다듬습니다
- **어떻게**: AI 가 제안하고, 확장이 검사하고, **사람이 승인한 것만** 적용합니다

### 페르소나가 방식을 정한다

특성 탭에서 고른 페르소나가 에이전트의 동작 방식 전체를 정합니다 (`shared/persona.js`).

| 방식 | 하는 일 | 해당 페르소나 |
|---|---|---|
| 새 화면으로 다시 구성 | 페이지에서 검색창·버튼·목록·본문을 뽑아 새 화면으로 그린다. 원래 페이지는 읽기만 한다 | 어르신, 어린이, 저시력, 난독, 손 떨림 |
| 소리 중심 화면 | 같은 재구성 화면을 음성 메뉴·숫자 키·화살표 키·말로 조작한다 | 시각장애 |
| 시각 중심 맥락 화면 | 핵심 정보와 자막·소리 상태를 전체 화면의 글자 패널로 보여 준다 | 청각장애 |
| 원래 화면에 모양만 | 요청할 때만 CSS 와 도움 부품을 더한다 | 설정 안 함 |
| (자동 또는 직접 선택) | 적은 글에서 방식을 끌어낸다. "잘 안 보여요"는 다시 구성, 전혀 못 볼 때만 소리 중심 | 기타 · 직접 적기 |

### 모드마다 하는 일이 다르다

같은 재구성 화면이라도 누구를 위한 것이냐에 따라 고유 기능이 붙습니다 (`shared/persona.js` 의 `features`, 같은 기능 묶음을 가진 모드는 없습니다).

| 모드 | 고유 기능 |
|---|---|
| 어린이 | **쉬운 요약**(문서를 어린이 말투로 한두 문단) · 중요한 부분에 **밑줄** · 모를 만한 낱말을 누르면 뜻이 나오는 **작은 사전** |
| 어르신 | 아주 쉬운 말의 요약 · 버튼마다 **"누르면 어떻게 되는지"** 한 줄 설명(다른 사이트로 나가는지, 바로 실행되는지, 한 번 더 묻는지) |
| 시각장애 | **목차 듣고 고르기** · **본문 이어 듣기**(`B` 키, 문단 번호를 알려 주며 끝까지) · 음성 메뉴 · 말로 조작 |
| 저시력 | **한 문단씩 아주 크게 보기**(앞 · 다음 문단) · 고대비 · 큰 글자 |
| 난독 | **한 문장씩 줄을 나눠 보기** · 문단 읽어 주기(읽는 문장을 따라 표시) · 작은 사전 · 넓은 글자 간격 |
| 손 떨림 | **자동 선택(스캔)**: 버튼을 차례로 비춰 주고 스페이스 · 엔터 한 번으로 고름 · 크고 간격 넓은 버튼 · 숫자 키 |
| 청각장애 | 원래 페이지를 두고 핵심 정보 · 자막 · 소리 상태를 글자 패널로 |
| 기타 | 적은 글에서 위 기능을 골라 붙임 ("초등학생, 어려운 단어를 몰라요" → 쉬운 요약 · 밑줄 · 작은 사전) |

본문은 `<p>` 문단을 먼저 읽고, 글이 거의 안 잡히면(나무위키처럼 `<p>` 를 쓰지 않는 사이트) 태그와 클래스에 기대지 않고 글자 덩어리를 직접 찾습니다. 요약은 언제나 **한 문단 이상**입니다(문단 하나는 3~5문장). 분량은 본문 길이를 따라갑니다: 1,500자 미만은 한두 문단(110자 이상), 6,000자 미만은 세 문단(260자 이상)과 요점 4개, 그 이상은 네 문단(380자 이상)과 "핵심 정리" 요점 7개. AI 가 한 문장으로 끝내면 분량을 알려 주고 **한 번 다시 받습니다**. 요약을 쓰지 않는 방식(손 떨림 · 청각장애 등)의 맨 위 설명도 첫 문장 하나가 아니라 한 문단이고, 그 아래 "이 글의 핵심"에는 이어지는 내용이 들어갑니다. 긴 문서는 앞 6문단과 문서 전체에서 고르게 뽑은 문단을 AI 에 보내 앞부분만 요약되는 일을 막습니다.

쉬운 요약 · 밑줄 · 작은 사전은 AI 가 글자만 돌려주고 검증을 거칩니다: 요약은 분량 계획이 허용하는 문단 수까지, 밑줄은 요약 안에 실제로 있는 구절만, 낱말 풀이는 요약이나 원문에 실제로 나오는 낱말만 받습니다. 화면에는 "AI 가 원문을 줄였어요. 정확한 내용은 원래 화면에서 확인해 주세요"를 함께 보여 줍니다. AI 가 없으면 원문의 앞 문장으로 대신하고 밑줄과 풀이는 지어내지 않습니다.

페르소나를 고르면 즉시 적용됩니다: 보기 설정(글자 크기·화면 색)을 그 방식에 맞게 되돌리고, 지금 보는 웹페이지에 직접 알려 다시 구성합니다.

### 작동 흐름 (팀 시스템 구조도 기준)

```
접속
 └ ① 사용자 특징 인식   데이터 수집 → 특징 분석 → 사용자 프로필 / 맥락 모델
     └ ② 설계 및 제안    후보 생성 → 최적 선택 → 사용자에게 제안
         └ 만족?
             ├ 예   → 적용 및 사용 → 사용 중 피드백 계속 수집 ─(지속적 개인화)→ 프로필
             └ 아니오 → ③ 대안 제안  불만족 신호 → 원인 추론 ─(학습 반영)→ 프로필
                                      → 다른 형태 생성 → 대안 제안 ─(재평가)→ 만족?
```

| 구조도 | 구현 | 상태 |
|---|---|---|
| ① 데이터 수집: 행동 로그 | 확대, 되읽기, 연타, 체류 시간, 자주 누르는 버튼 (방문이 끝날 때 기록) | 일치 |
| ① 입력 패턴 | 키보드 비율, 빗나간 클릭, 타자 속도, 지우기 비율, 첫 조작까지 시간 | 일치 |
| ① 선호 | 좋아한 설계, 거절 기억, 전략 선호, 정보량 선호, 직접 고친 값 | 일치 |
| ① 이용 환경 | 브라우저가 알려 주는 값만 (다크 모드·동작 줄이기·고대비·터치·확대 배율·화면 너비·언어) | **부분** — 기기 종류, 스크린리더 사용 여부는 모른다 |
| ① 특징 분석 | 숙련도 · 목적 · 인지 스타일 · 상황 맥락 · 접근성 필요를 근거와 함께 추론. 사용자가 보고 고칠 수 있다 (`shared/profile.js`) | 일치 |
| ② 후보 생성 | 모양만: AI 한 번 호출로 전략이 다른 3개. 재구성: AI 후보 + 로컬 후보(핵심·보통·자세히) | 일치 |
| ② 최적 선택 | 안전 감사 + 실제 페이지 측정 → 채점(안전 30 · 타당 25 · 목표 25 · 적합 20) → 1위 | 일치 |
| ② 제안 → 만족? → 적용 | 모양만: 검토 카드에서 승인해야 적용. 재구성: 페이지를 열면 원래 페이지를 가리지 않는 카드로 먼저 제안("바꿔 보기 / 이 사이트는 항상 / 원래 화면으로")하고, 받아들이면 띄운다. 소리 중심 사용자에게는 읽어 주고 엔터 · Esc 로 답한다. "항상"을 고른 사이트와, 방금 페르소나를 고른 경우(그 자체가 요청)는 바로 띄운다 | 일치 (하네스에서만 확인) |
| ③ 불만족 신호 | 모양만: 거절, 검토 안 하고 떠남, 망설임, 빠른 되돌림, 적용 후 연타, 부정 응답, 이어지는 어려움. 재구성: 평가에서의 거절, 이탈(12초 안에 아무것도 안 하고 닫음), 망설임(30초 무조작), 조작 오류(빗나간 클릭 · 없는 번호 · 못 알아들은 말) | 일치 (재구성 쪽은 하네스에서만 확인) |
| ③ 원인 추론 | 너무 큼 · 불안 · 불편 · 다름 · 결정 어려움 · 버튼이 안 눌림 (`shared/alternatives.js`) | 일치 |
| ③ 학습 반영 | 원인이 프로필에 쌓이고(`learnFromDissatisfaction`), 같은 종류가 되풀이되면 내용의 양 · 안내 방식 · 선호 형태 추론이 바뀐다. 한 번으로는 바뀌지 않고, 근거가 특성 탭에 보이며, 직접 고친 값이 우선. 거절 기억·전략 선호·정보량 선호에도 함께 쌓인다 | 일치 (숙련도는 바꾸지 않는다) |
| ③ 다른 형태 | 모양만: 약하게 다시(시각) · 읽어주기(음성) · 요약(텍스트) · 하나씩 고르기(단계형). 재구성: 정보량 변경(시각) · 소리로 듣기(음성) · 글로만 보기(텍스트) · 하나씩 고르며 보기(단계형) · 원래 화면. 시도한 형태는 되풀이하지 않고, "편해요"라고 한 형태는 다음에 먼저 보여 준다 | 일치 |
| ③ 재평가 | 최대 2회, 같은 형태 반복 금지, 같은 검토·평가로 다시 들어간다 | 일치 |
| 지속적 개인화 | 방문마다 프로필 갱신, 맞춤 화면에서도 어려움이 이어지면 ③으로, "좋아요" 한 설계는 이후 제안에 반영 | 일치 |

## 2. 안전 설계

목표는 하나입니다. **AI 가 만든 것이 사람의 승인 없이 페이지에 닿지 못하고, 기존 버튼의 기능을 바꿔치기하지 못하게 한다** (예: '검색' 버튼이 '메일 보내기'를 하게 되는 일).

| 겹 | 내용 |
|---|---|
| 1. 쓸 수 있는 것을 좁힌다 | AI 는 CSS 와 **정해진 부품 8종**(안내 카드, 단계 안내, 목차, 바로가기, 낱말 풀이, 읽어주기, 맨 위로, 글자 크기 조절)만 낼 수 있다. HTML·JS 를 돌려줘도 버린다. 바로가기는 대상으로 스크롤해 보여 주기만 하고 대신 누르지 않는다. 재구성 화면의 버튼은 페이지에서 뽑은 참조 번호로만 연결되고, 없는 버튼은 버리며, 이름을 다른 뜻으로 바꾸면 실제 이름으로 되돌린다 |
| 2. 적용 전 정적 감사 | 외부 전송·`@import`·스크립트성 구문·안전 UI 를 겨냥한 선택자는 **제거**. 버튼·입력창을 숨기는 CSS, 글자 바꿔치기, 전역 숨김, 기존 버튼에 새 동작을 붙이는 코드는 **경고로 검토 카드에**. 로그인·결제·금융 페이지는 CSS 외 전부 차단 (`shared/safety.js`) |
| 3. 실제 페이지에서 측정 | 후보를 잠깐 입혀 보고 잰 뒤 되돌린다: 못 쓰게 되는 버튼, 사라지는 본문, 떨어지는 대비, 가로 넘침, 조각나거나 잘리거나 겹친 테두리, 효과 없음. 문제가 나오면 측정값을 돌려줘 **한 번** 자동 수리 |
| 4. 채점에서 안전이 가장 크다 | 100점 중 30점. 안전 문제가 있는 후보는 1위가 될 수 없다 |
| 5. 사람 승인 | 기본은 "항상 검토 후 적용". 제안은 **페이지에 바로 입혀서 보여 주되 저장하지 않는다**(모양과 도움 부품까지, 동작 스크립트는 승인 전에는 실행하지 않음). 아래쪽 띠에서 후보 버튼을 누르면 그 후보로 바로 바뀌고, "원래 화면과 비교"로 되돌려 볼 수 있으며, 마지막 선택은 사용자가 한다: 승인(항상) / 이번만 / 거절. 위험도·경고·측정한 변화·코드는 "자세히"에 있다. 고위험은 확인 체크를 해야 승인 버튼이 열린다. 저장된 맞춤 화면도 방문할 때마다 다시 감사한다 |
| 6. 언제든 되돌리기 | `Alt+Z` 로 즉시 원래 화면 + 그 사이트 자동 적용 끔. 재구성 화면은 Esc. 재구성 화면에서 결제·삭제 같은 버튼은 누르기 전에 한 번 더 묻는다 |
| 7. 격리와 개인정보 | 페이지 안 UI 는 closed Shadow DOM. 확장 자체 화면에는 AI 코드가 들어가지 않는다. 입력한 글자·방문 주소 전체는 저장하지 않고 횟수·비율·짧은 버튼 이름만 기기에 남긴다. 먼저 제안하기는 사이트당 하루 1회, 제목과 측정값만 보낸다. 소리 받아쓰기는 직접 누른 탭에서만, 조용한 구간은 보내지 않고, 녹음을 저장하지 않는다 |

**실제 사이트에서 깨진 사례는 3단으로 막습니다** — 가드(`shared/css-quality.js`가 적용 전에 고침) · 측정(검증기가 잼) · 작성법(AI 프롬프트의 검증된 작성법) + 회귀 테스트. 지금까지: 모든 링크에 상자를 둘러 제목 위로 선이 지나감, 탭 줄에서 테두리가 잘려 세로 막대만 남음, 붙어 있는 아이콘 버튼의 선이 겹침, 버튼에 배경만 칠해 글자가 안 보임.

**빈틈**
- 캔버스 에디터(요소를 직접 골라 편집)의 **"동작 추가"는 이제 AI 가 코드를 쓰지 않고 정해진 동작 13종**(맨 위로, 스크롤, **다른 페이지로 이동**, 보이기·숨기기, 안내 문구, 읽어 주기, 강조, 글자 크기, 입력 칸으로, 알림 소리, 색종이, 흔들기, 횟수 세기 — `shared/actions.js`)**에서 고른다.** 기본은 원래 기능을 그대로 두고 동작을 더하며, 네트워크·제출·저장소·클립보드 동작은 목록에 없다. "다른 페이지로 이동"은 버튼이 엉뚱한 곳으로 데려가는 일을 막기 위해 따로 묶어 둔다: 목적지는 http(s) 주소만, **지금 페이지에 실제로 있는 링크이거나 사용자가 요청에 직접 적은 주소**여야 하고(AI 가 지어낸 주소는 버린다), 누를 때만 동작하며, 어디로 가는지가 에디터의 설명과 요소의 말풍선에 항상 드러난다. 예전 방식(AI 가 쓴 스크립트를 `<script>` 로 주입)은 대부분의 사이트에서 CSP 에 막혀 조용히 실패했고, 과거 저장분 호환용으로만 남아 있다(막히면 실패로 알린다). 에디터의 모양 편집과 요소 추가는 여전히 자유 HTML 을 다룬다. 그래서 **기본은 꺼 두었고**, 설정 탭에서 "캔버스 에디터 (실험 기능)"를 켠 경우에만 버튼이 보이고 열린다.
- API 키는 시연용이라 확장 폴더(`shared/env.local.js`)에 평문으로 들어간다. 폴더를 남에게 주거나 스토어에 올리면 안 된다.
- 감사는 규칙 기반이라 새로운 우회 패턴은 사례가 나올 때마다 규칙과 테스트를 추가한다.

## 3. 핵심 기능

| 기능 | 설명 | 위치 |
|---|---|---|
| 화면 다시 구성 | 페이지를 읽어 검색창·주요 버튼·주요 내용만 있는 새 화면으로. "더 간단하게 / 더 자세히", 숫자 키, 이전·다음 페이지. AI 가 없어도 로컬 설계로 항상 뜬다 | `content/extractor.js`, `shared/layout.js`, `content/rebuild.js` |
| 소리 중심 조작 | 화면 안내 읽기, 숫자 키로 버튼, 화살표로 내용, `/` 입력, `R` 다시 듣기, `H` 도움말, 말로 조작("일 번", "다음", "검색 날씨") | `content/rebuild.js` |
| 말로 하는 화면 재구성 | 정해진 명령이 아닌 말("학사일정이랑 학교소식을 오른쪽으로 옮겨 줘", "글자 더 크게", "내용은 숨겨 줘", "원래대로")을 화면 배치 요청으로 받아 재구성 화면을 다시 짠다. 자주 쓰는 말은 AI 없이 알아듣고, 그 밖은 AI 에 묻는다. 바꿀 수 있는 것은 구역 순서 · 버튼 위치·순서·열 수 · 글자 크기 · 숨김뿐이고(허용 값만 통과), 원래 페이지와 버튼 연결은 건드리지 않는다. 사이트별로 기억한다. 글로도 요청 가능("배치 바꾸기") | `shared/layout.js`, `content/rebuild.js` |
| 펼침 메뉴 읽기 | 마우스를 올려야 나오는 하위 메뉴를 묶음 이름과 함께 읽어 '메뉴' 구역으로. `M` 키로 전부 듣기, 항목 이름을 말하면 열림. 이름과 연결은 페이지 값 그대로. 재구성 화면을 쓰지 않을 때는 "화면 설명"이 묶음 이름과 항목을 읽어 준다 | `content/extractor.js` |
| 모양만 맞춤 | "글자 크게", "광고 정리", "버튼 또렷하게" 같은 요청 → 후보 3개 → 검토 카드 → 승인. 사이트별로 저장해 다시 오면 자동 적용 | `background/service-worker.js`, `content/content.js` |
| 도움 부품 | 안내 카드, 단계 안내, 목차, 바로가기, 낱말 풀이, 읽어주기, 맨 위로, 글자 크기 조절 | `content/parts.js` |
| 바로 켜기 | 화면 다시 구성, 화면 설명, 읽어주기, 자막 크게, 쉬운 요약 (AI 를 거치지 않아 빠르고 비용이 없다) | 사이드 패널 · 팝업 |
| 소리 → 글자 | 자막 없는 영상의 탭 소리를 5초 구간으로 받아써 자막 바에 표시. OpenAI · Gemini · OpenRouter 키 모두 지원 | `offscreen/transcriber.js` |
| 특징 인식과 프로필 | 추론한 숙련도·인지 스타일·필요를 근거와 함께 보여 주고, 사용자가 고칠 수 있다 | `shared/profile.js`, 특성 탭 |
| 기능 추천 | 페이지 신호(긴 글, 영상, 작은 글자)와 수락률로 추천. 싫다고 한 기능은 다시 권하지 않는다 | `shared/recommender.js` |
| 대안 제안 | 거절·되돌림·망설임에서 원인을 추론해 다른 형태로 최대 2회 | `shared/alternatives.js` |
| 접근성 새 탭 | 큰 입력 상자, 말로 검색, 자주 가는 곳, 화면 설명 듣기, 보기 설정(글자 크기·화면 색·간격·단순하게·읽어주기) | `ui-src/src/features/NewTab.tsx` |
| 긴급 복구 | `Alt+Z` 원래 화면, `Alt+Shift+U` 사이드 패널 | `manifest.json` |

### 기술

| 영역 | 사용한 것 |
